# V2 rebuild decisions

## Scope

The new local directory is separate from the existing project, original source project, public repository and deployed architecture website. No old files were deleted or published as part of this rebuild.

The core question is: can this customer quote be supported by current engineering evidence, available capacity and checked arithmetic?

## Keep in the first working loop

Generated sources, safe conversion, resumable ingestion, scoped current-version retrieval, confirmed preference memory, quote/capacity handoffs, a revision-bound manager review boundary, offline evaluation and a small evaluation studio.

## Defer

Airflow/Snowflake warehouse operations, delivery-risk ML, the original six-module architecture explorer, distributed A2A transport, live LLM inference, live Redis/Inngest/LangSmith, and AWS deployment are outside this first V2 acceptance. Existing V1 work remains available for comparison and later decisions. This prevents a diagram from promising integrations that the local runtime does not exercise.

## Data and authority

All names and data are invented. Capacity comes from the local source snapshot. Costs come from checked numeric BOM formulas. ECN lead days are controlled metadata validated against the document body. Conversational preferences cannot override these facts. Internal proposal approval neither sends a quote nor allocates capacity.

## Evaluation hierarchy

1. Validate source contracts and formula consistency.
2. Check retrieval scope, current version and required evidence.
3. Assert arithmetic, delivery constraints, capacity and review binding.
4. Deliberately corrupt outputs and fail publication at both transaction boundaries.
5. Compare results across authored cases and parameter combinations.
6. Keep real-model and production qualification blocked until measured independently.

## Limitations to resolve next

Local single-user SQLite does not model distributed concurrent reservations. Source permissions are enforced through the trusted service scope, not a production identity provider. Document deletion is logical suppression: raw snapshots, historical graph checkpoints and backups require a separate retention/purge implementation. Preference deletion removes rows from the local preference store; historical workflow checkpoints may retain earlier context. A complete privacy deletion workflow is not implemented.

The restricted formula evaluator, lexical-hash vector retrieval, rule router, structured compaction and typed handoffs are intentionally small and explicit. Unsupported inputs fail for review rather than being silently guessed. Replacement by real integrations requires contract tests, data validation, access checks and performance evidence; changing a source path alone is insufficient.
